# 自动录音临上课开启漏录

Remember 1.0.2+43，2026-10-31。

用户报告：临上课前打开自动录音，偶发整节未录。

已在原版隔离复现：

1. Flutter 只登记 `start > now`。10:05 开课时，10:04:59.999 仍登记，准点、晚 1 毫秒或晚 1 分钟均跳过当堂。权限等待或排期计算跨过边界即可触发。
2. 录音页排期忙碌时直接返回。旧关闭请求正在撤销闹钟时打开开关，界面与偏好为开启，但原生只收到空排期，完成后没有补跑。
3. 原生先取消旧闹钟，再跳过已到时的新闹钟，刷新跨过上课时间会取消当堂且不补登记，仍返回成功。
4. 冷服务原先先登记闹钟、再异步布防，极近开课边界时闹钟可能先于服务就绪。

修复：保留未下课的当堂，传递稳定的原始开课与下课时间；原生以当前时间及时触发，仍在原定课末停止。排期请求串行，页面忙碌变更合并重跑。服务就绪且同步布防成功才安装闹钟。同一堂成功开始后不因刷新或手动停止而重复启动；手动录音不被覆盖。

验证：原版 Dart 两项复现、原版 Kotlin 三项隔离 JVM 复现；修复后 Flutter 33 项（含刚更新的转写任务管理回归）、Android Robolectric 13 项、后端相关 34 项通过；Dart lib 分析无问题。双端编译及签名另有任务目录证据。测试使用虚构课程与隔离目录，没有登记真机闹钟或读取真实音频。

显示品牌统一 Remember；保留 Android 包名、平台通道、偏好键、数据路径、AUMID 与内部 APK 路径。GitHub 仓库名、Release 标题及附件需要单独核实，源码提交不代表这些外部元数据已变更。

实体手机临上课开启、锁屏到点、HyperOS 后台与覆盖安装仍需更新后验收。未取得发生漏录当天的手机日志，以上是实测可复现且符合现象的代码缺陷，不能据此断言每次历史漏录只有同一原因。
